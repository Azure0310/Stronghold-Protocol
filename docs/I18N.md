# 多言語化（日本語版）

ソース言語は中国語（zh-CN）のまま。画面に出る文字列は `t('中文原文')` を通し、言語ごとの辞書（`/i18n/ja.json`）で置き換える。辞書にないキーは中国語のまま表示されるので、翻訳が途中でも画面に穴は開かず、中国語を比較するロジック（`reason === '资金不足'` など）も壊れない。

言語は `?lang=ja|zh`（記憶される）→ localStorage `sp.lang` → ブラウザの言語（ja なら日本語）→ 中国語の順で決まる。タイトル画面と設定に切り替えスイッチがある（切り替えるとページを再読み込みする）。

## 仕組み

| 部品 | 役割 |
|---|---|
| `public/js/i18n.js` | `t(key, params)`、`lang`、`localizeJson(json)`、`switchLang(id)`。辞書は top-level await で読み込むので、モジュール直下の定数で `t()` を呼んでよい |
| `public/js/data.js` | `/data/*.json`（表示用コピー）を読み込んだ直後に `localizeJson` で文字列を置換する。ブラウザ内シミュレーションは別に生のデータを取得する（`battle/runner.js`）ので、戦闘計算には影響しない |
| `i18n/ja/*.json` | 翻訳の元ファイル。`{ "中国語原文": "日本語訳" }` の平らなオブジェクト。ファイル名順に読み込み、後のファイルが前を上書きする |
| `i18n/glossary.ja.md` | 用語集。**翻訳は必ずこれに従う** |
| `tools/i18n.mjs` | `build`（`i18n/ja/*.json` → `public/i18n/ja.json`）、`coverage`（未翻訳の一覧）、`lint`（`t()` の外に残った中国語） |
| `public/i18n/ja.json` | 生成物（ブラウザが読む）。直接編集しない。コミットしない（`.gitignore` 済み）。`npm install`（postinstall）と `npm run setup` が作る |

`i18n/ja/` のファイル構成:

- `00-official.json` — 日本版公式データ（Yostar の ja_JP）から**手元で自動生成**する（オペレーター名、スキル、素質、敵など）。権利は Yostar / Hypergryph にあるのでコミットしない（`.gitignore` 済み）。`npm run setup`（`--no-ja-official` で省略）か `npm run i18n:official` が `tools/i18n-official.mjs` を実行して作る。無くてもゲームは動くが、その分の名称や説明は中国語のまま表示される
- `10-ui-*.json` — 画面の文言（手訳）
- `20-data-*.json` — ゲームデータのうち公式データで埋まらないもの（手訳）
- `30-server.json` — サーバーが送る文言（手訳）

## コードの書き方

```js
import { t } from '../i18n.js';           // ファイルの位置に合わせて相対パスを調整

html`<button>${t('升级')}</button>`        // 中国語の文字列リテラルはキーとして t() に渡す
t('已拥有 {copies}/{need}', { copies, need })   // 埋め込みは名前付きプレースホルダ。キーは静的な文字列だけ（${} は使わない）
title=${t('价格')}                            // 属性にも使う
```

- **キーは原文と完全一致**させる（空白・句読点・全角半角も）。`+` で文字列をつなぐ代わりに、1 つのキーにプレースホルダを入れる。
- プレースホルダ名は日本語訳でも同じにする。語順は日本語に合わせて入れ替えてよい。
- **ロジックに使う文字列は翻訳しない**: `===` で比較する、`switch`/Map のキー、正規表現、データ ID、CSS クラスなど。表示する場所だけ `t()` を通す（`reason === '资金不足'` はそのまま、画面に出すときに `t(reason)`）。変数を渡す `t(reason)` は静的に検出できないので、**取りうる値は辞書に入れる**（`coverage` はコード中の `t('…')` と `shared/` の中国語リテラルだけを見る）。
- 中国語のまま残す行（ロジック用の比較・正規表現など）は行末に `// i18n-ok` を付ける（`lint` の対象外になる）。
- `shared/` は Node（サーバー）でも動くので `t()` を import しない。そこにある中国語の文言は辞書のキーとして翻訳し、クライアントが表示するときに `t(ERR_TEXT[code])` のように通す。
- サーバーが組み立てた文言（`m.toast`、`m.ticker` など）は、表示する側で `t(text)` を通す。数値が埋まった文は、辞書に `{name}` 入りのキーを入れておけば自動でパターン照合される（`已拥有 {a}/{b}` → `{a}/{b} 所持`）。
- **同じ中国語で意味が違う語**（「关闭」＝閉じる／OFF、「冻结」＝ショップのロック／状態異常の凍結）は、特別なほうの用法に文脈を付ける: `t('关闭', null, 'toggle')`。辞書には `"toggle::关闭": "OFF"` と書く（`文脈::原文`）。文脈つきを先に探し、無ければ文脈なしのキー（`"关闭": "閉じる"`）にフォールバックする。文脈名は `toggle`（ON/OFF 切替）、`shop`（ショップ操作）のように用法を表す短い英単語。
- コメントは翻訳しない。

## 作業の流れ

```bash
node tools/i18n.mjs lint --list 0          # t() の外に残った中国語をファイルごとに数える
node tools/i18n.mjs lint --file ui/hud.js  # 1 ファイルの該当行を全部出す
node tools/i18n.mjs build                  # 辞書をビルド（プレースホルダ・タグの不一致があればエラー）
node tools/i18n.mjs coverage --list 20     # 未翻訳のキーを出す（--json out.json で全件）
```

ブラウザで確認: `http://localhost:3000/?lang=ja&i18n=debug` を開くと、翻訳のない中国語の文字列がコンソールに 1 回ずつ出る（`__i18nMissing` にも溜まる）。

## 辞書のルール

- 値が空の項目は無視される。値が原文と同じ（中国語のまま）の項目は作らない。
- プレースホルダ（`{name}`）とリッチテキストタグ（`<@ba.vup>…</>`、`<$ba.xxx>…</>`）は、キーと値で**同じものが同じ数**になっていなければならない（`build` が検証する）。
- 同じ原文が別の意味で使われている場合だけ、キーを区別する必要がある。まず `i18n/ja/10-ui-*.json` のどこかに既にないか検索してから追加する。

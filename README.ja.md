## 概要

「卫戍协议：盟约」はオートチェス＋タワーディフェンス。準備フェーズに調度センターでオペレーターを募集し、配置し、装備を整える。戦闘期にはオペレーターが自動で展開し、赤い門から押し寄せる敵を迎え撃つ。通り抜けた敵は目標ライフを減らす。本プロジェクトはこの遊びをブラウザ上で再現したもので、ルールと数値はできる限り公式データ表と PRTS で照合している。

- **単独演算**（ソロ）と**連合演算**（1〜4 人の**協力**。PvP はない。空き枠には AI の仲間を入れられる）。
- サーバーは Node.js のプログラム 1 つで、**戦闘は各プレイヤーのブラウザ内でシミュレート**される（公式と同じ）。サーバーは経済とラウンド進行だけを担当するので、省電力の小型 PC でもサーバーを立てられる。
- 現行バージョンは 0.1.3。0.1.2 公開後にプレイヤーと GitHub で寄せられた問題を修正した。詳細は [CHANGELOG.md](CHANGELOG.md)。一部のルールは推測で実装していて、公式と違う点があれば Issue で教えてほしい（ゲームの仕組みに関する報告は上流へ）。

## 機能一覧

- **1 ゲームの通し**：ゲーム情報の確認 → 戦略ドラフト（40 種の戦略）→ 14 ラウンド → 称号の結果。「険境」以上で条件を満たすと第 15 ラウンド「隠された核心」に進む。
- **4 つの難易度**：標準 / 険境 / 絶境 / 究極。単独と連合でそれぞれ別のパラメーターを持ち、いずれも公式データに基づく。
- **準備フェーズ**：募集、更新、ロック、調度センターのレベルアップ。整備エリアと臨時整備エリア。整備エリアから盤面へドラッグして配置し、**方向ホイール**で向きを選ぶ。連合演算ではカードプールが共通。
- **エリート昇進**：同名のオペレーター 3 人が自動でエリートに合成され、1 段階上の無料募集を 1 回得る。
- **オペレーターと編成**：募集可能な 112 人のオペレーター（＋エリート）とそのスキル・素質・特性。開始前に、各オペレーターが持つスキル（283 個すべて手作業で実装）とエリートのモジュールを選べる。
- **盟約と層数**：23 の盟約（8 つの勢力コア盟約＋追加盟約）。層数はゲーム中ずっと保持され、盟約ごとに最大 999 層。
- **装備と機変**：装備と術式。同名装備の合成、特定の組み合わせによる盟約効果の付与。配布済みの装備はオペレーターに固定される。一部のラウンド開始前に機変カード選択（装備・資金・オペレーター・層数・懸賞など）がある。
- **自動戦闘**：スキルは公式の「スキル戦略」に従って自動で発動する。接触半径によるブロック（ブロック役が倒れると接触中のオペレーターが交代）、元素損傷と元素爆発、召喚物はプレイヤーが手動で配置、押し出し / 引き寄せは強さと重さで計算、倒されたオペレーターはその場に再配置までのカウントダウンを表示して残る。
- **地形と敵**：遮断バリケード、射撃台、源石流ブロワー、沼地、排気グリル、満ち潮などの地形装置。空中および低空浮遊の敵、懸賞敵。
- **連携防衛**：敵を漏らした人がいて、完璧に戦った仲間もいる場合、完璧に戦った仲間が自分の編成で、漏れた敵の迎撃を手伝う。
- **最終攻勢と隠された核心**：2 人で 1 つの戦場を共有し、全員で同じリーダーの HP バーを削る。10 体の敵リーダー、約 5×3 マスの被弾範囲を持つ巨大リーダー、公式のダメージ制限ルール。
- **結果の称号**：「衛戍の星」「不朽の盟約」「堅牢なること磐石の如し」など 6 つの称号。
- **切断からの復帰**：連合演算では切断後 10 分以内にページを開き直せば元の席に戻れる。切断中は元の編成で自動戦闘し、「離席」して AI に任せることもできる。単独演算は 24 時間以内なら（同じブラウザで）続きから遊べる。
- **操作まわりの細部**：敵を漏らすと上部バーの目標ライフがリアルタイムで減る（確定は結果画面）。選択・ドラッグ＆ドロップ・装備の配布はすべて地面のマス基準。購入・レベルアップ・機変カード選択は 2 回タップして確定する。プレイヤーが 1 人のときは戦闘以外に制限時間がない。
- **映像と音**：本物の Spine ミニキャラ、公式の BGM と効果音、スタンプ（6 セット × 6 個）、戦闘エフェクト。任意で公式の 3D 盤面も使える（ローカルのクライアントからテクスチャを抽出する必要がある）。
- **スマホと PC**：タッチでドラッグ、長押しで詳細表示。横画面を推奨。設定で画質を下げられる。
- **日本語表示**：画面の文言・オペレーター・スキル・敵・盟約などを日本語で表示（`?lang=ja`、または設定の「中文 / 日本語」で切り替え）。

## クイックスタート

### ソースから実行

日本語表示はこのリポジトリのソースに入っている。上流の Releases にある素材入りの同梱パッケージは日本語化を含まない中国語版なので、日本語で遊ぶには次の手順でソースから動かす（このリポジトリは素材入りのパッケージを配布しない）。

1. **Node.js 22 または 24（LTS）をインストールする**
   - Windows：PowerShell で `winget install OpenJS.NodeJS.LTS` を実行するか、<https://nodejs.org/ja/download> からインストーラーを入手する。
   - macOS：`brew install node@22`、または公式サイトのインストーラー。
   - Linux：ディストリビューションのパッケージマネージャー、nvm、fnm。
2. **取得・セットアップ・起動**

```bash
git clone https://github.com/Azure0310/Stronghold-Protocol.git
cd Stronghold-Protocol
npm install        # 依存をインストール（postinstall が pixi / preact / three を public/vendor にコピーし、日本語の辞書をビルドする）
npm run setup      # 環境を確認し、公開ミラーから美術 / 音声（約 270 MB）と日本版の公式テキスト（約 100 MB）を取得（中断可。再実行すると続きから）
npm start          # サーバー起動：http://localhost:3000
```

3. ブラウザで `http://localhost:3000/?lang=ja` を開く（ブラウザの言語が日本語なら、`?lang=ja` がなくても最初から日本語）。

起動スクリプト（Windows は `scripts\start-windows.bat`、macOS / Linux は `scripts/start.sh`）を直接実行してもよい。初回は依存のインストール・素材の取得・日本語の公式テキストの生成を自動で行い、そのあとサーバーを起動してブラウザを開く。ウィンドウに表示される LAN のアドレスは、同じネットワークの友達にそのまま送れる。ウィンドウを閉じる（または `Ctrl+C`）とサーバーが止まる。

- `npm run setup` は次の順に進め、済んでいる手順は飛ばす：Node の確認 → 依存 → `public/vendor` → ゲームデータ → 美術 / 音声 → **日本語の辞書（公式テキストの生成とビルド）** → ローカルクライアントの素材（任意）。
- 日本版の公式テキスト（`i18n/ja/00-official.json`）は Yostar / Hypergryph の著作物なので、リポジトリには入れず、手元で生成する。生成を省くには `node tools/setup.mjs --no-ja-official`（手訳した画面の文言だけが日本語になり、オペレーター・スキル・敵の名称と説明は中国語のまま）。あとから生成するには `npm run i18n:official`。
- 美術 / 音声は要らない（占位表示でよい）ときは `--no-assets`、ローカルクライアントの抽出を飛ばすときは `--no-local`。
- 素材のダウンロードはまず GitHub を使い、失敗すると自動で jsDelivr ミラーに切り替わる。
- `npm run doctor`（`node tools/doctor.mjs`）でいつでも診断できる：Node のバージョン、素材がそろっているか、ポートの使用状況、LAN アドレスとファイアウォール。

### ローカルクライアントの素材（任意）

公式の 3D 盤面、公式 UI アイコンの一部（交流ボタンやスタンプパネルの枠、モジュール種別アイコンなど）、灼熱 / 熾炎源石虫の公式モデルは、手元の『アークナイツ』PC クライアント（Windows ネイティブ、macOS の CrossOver または PlayCover）から抽出する必要がある。`npm run setup` はクライアントを検出すると抽出するか尋ねる（Python 3.8 以上が必要。依存はプロジェクト内の `.venv-extract` に入り、システムには影響しない）。あとから `node tools/setup.mjs --local` で再抽出するか、`--game "<…/StreamingAssets/AB/Windows>"` でパスを指定できる。クライアントがなくてもゲームは普通に動き、これらは代替表示になる：2D 盤面、似た見た目のアイコン、色違いの通常の源石虫。スタンプと「遊び方」のチュートリアル画像は上記の素材と一緒に公開ミラーからダウンロードされ、クライアントは不要。詳細は [docs/DEPLOY.md](docs/DEPLOY.md) の「ローカルクライアント素材」を参照。

### 動作環境

| 項目 | 要件 |
|---|---|
| サーバーを立てる PC | Windows / macOS / Linux、Node.js 22 または 24（LTS）。ディスクは約 400〜500 MB（素材・依存・任意のローカル抽出テクスチャ）。空きメモリは約 100 MB、1 ゲームごとにさらに数 MB |
| プレイヤー | WebGL 対応の最新ブラウザ（Chrome / Edge / Firefox / Safari の最新版）。PC・スマホ・タブレット（横画面） |
| ネットワーク | 初回のゲーム参加時に、各プレイヤーがサーバー PC から数十 MB の素材をダウンロードする（以後はブラウザのキャッシュ）。対戦中の通信量は小さい |

GPU が弱いときは「設定」で画質を下げるか、URL の後ろに `?board=2d`（2D 盤面を強制）/ `?render=fallback`（WebGL を使わない簡易表示）を付ける。

### ポートと設定

デフォルトは **TCP 3000** で待ち受ける。ポートを変えるには、起動スクリプトに `--port 3001` を付けるか、環境変数 `PORT` を設定する。

| 環境変数 | デフォルト | 説明 |
|---|---|---|
| `PORT` | `3000` | 待ち受けポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス（`127.0.0.1` = 本機のみ。リバースプロキシの背後に置くときに使う） |
| `SP_COMBAT` | `client` | `client`：各プレイヤーのブラウザが自分の戦闘をシミュレート（サーバー負荷は極小）。`server`：サーバーがシミュレートして配信 |
| `SP_VERIFY` | `off` | クライアントが報告した戦闘結果をサーバーで再計算する：`off` / `sample`（約 1/8 を抜き取り）/ `all`（すべて再計算。CPU 負荷が高い） |
| `TRUST_PROXY` | `auto` | `X-Forwarded-For` などの転送ヘッダーを信頼するか：`auto` は本機 / 内部ネットワークのプロキシだけ信頼、`1` は常に信頼、`0` は信頼しない |
| `DEBUG` | 空 | 何か値を設定すると詳細ログを出す |
| `SP_NO_BROWSER` | 空 | `1` にすると起動スクリプトがブラウザを自動で開かない |

設定方法：macOS / Linux は `PORT=8080 npm start`、PowerShell は `$env:PORT=8080; npm start`、cmd は `set "PORT=8080" && npm start`。ヘルスチェック：`GET /healthz`。

### 友達と遊ぶ（LAN）

1. ページを開く → ニックネームを入力 → **連合演算** → ルームを作成。ホストが難易度を選び、AI の仲間を追加 / 削除できる。開始前に、他のドクターを連合から外すこともできる（相手は連合キーで再参加できる）。
2. 4 文字の**連合キー**、または「リンクをコピー」で得られる `http://<アドレス>:3000/?room=キー` を友達に送る。
3. 全員が「準備完了」を押したら、ホストが開始する。
4. 同じ Wi-Fi / ルーターの友達は、起動ウィンドウに表示されたアドレス（`http://192.168.x.x:3000` の形）を開けばよい。開けないときはたいていファイアウォールが原因：Windows では初回起動時のダイアログで「プライベート ネットワーク」を許可するか、`npm run doctor` で具体的なコマンドを確認する。ゲスト用 Wi-Fi は「AP 分離」が有効なことが多く、これでもつながらなくなる。

ページを更新したり切断されたりしても、連合演算は 10 分以内、単独演算は 24 時間以内に開き直せば元の席に戻れる。サーバーはルームも対戦もメモリ上に保存しているので、**サーバーを再起動するとすべての対戦が終了する**。

## オンラインで遊ぶ方法

友達が同じ LAN にいないときの代表的なやり方を挙げる。自分の状況に合うものを 1 つ選べばよい。ここでは簡単に紹介するだけで、挙げたツールやサービスは例にすぎず、本プロジェクトとは無関係で、推奨もしない。インストール・費用・利用規約はそれぞれの公式の説明に従うこと。デプロイの詳細（ファイアウォール、自動起動、リバースプロキシと HTTPS、Docker）は **[docs/DEPLOY.md](docs/DEPLOY.md)** を参照。

| 方法 | やり方 | 向いている場合 |
|---|---|---|
| **同じ LAN で直接接続** | 起動ウィンドウの LAN アドレスを友達に送る | 同じ家・寮・ネットカフェ |
| **メッシュ VPN（仮想 LAN）ツール** | 例：Tailscale、ZeroTier、EasyTier、蒲公英。サーバーを立てる人と友達が同じツールをインストールして同じネットワークに参加し、友達はサーバー PC の仮想 IP で `http://<仮想 IP>:3000` にアクセスする | 決まった数人の知り合い。インターネットに公開しない。友達もクライアントが必要で、アカウント登録が要るツールもある。地域をまたぐと中継経由で遅くなることがある |
| **ポート開放不要のトンネル** | サーバーを立てる人だけがクライアントを動かし、友達は URL を開くだけ。例：自前の frp（グローバル IP を持つサーバーが必要）、Cloudflare の `cloudflared tunnel --url http://localhost:3000`（一時的なアドレスで、起動のたびに変わる）、各種の公開トンネルサービス（実名登録が必要なものや、地域によって Web ホスティングに届け出が必要なものがある） | ルーターをいじりたくない、グローバル IP がない場合。無料回線で帯域が小さいと、初回の素材読み込みが遅くなる |
| **クラウドサーバー / VPS に直接デプロイ** | VPS でソースを動かすか、リポジトリ付属の `Dockerfile` を使う（ビルドの手順は `Dockerfile` の冒頭と [docs/DEPLOY.md](docs/DEPLOY.md)）。Caddy / Nginx で HTTPS にする。プレイヤーに近く回線の良い地域を選ぶ（中国本土のプレイヤー向けなら、海外のデータセンターは戻りの経路に注意しないと、夜のピーク時に遅延が大きくなりうる。中国本土のサーバーでドメインを使うには ICP 届け出が必要） | 長期間サーバーを開けておきたい、プレイヤーが各地にいる場合 |

共通の注意点：

- ゲームは**常駐する Node.js プロセス 1 つ ＋ WebSocket**（パス `/ws`）で、インスタンスは 1 つしか動かせず、ドメインのルートパスにデプロイする必要がある。Vercel のようなサーバーレス基盤や GitHub Pages のような静的ホスティングは使えない。リバースプロキシは WebSocket のアップグレードを転送すること。
- ゲームにアカウントの仕組みはなく、**アドレスを知っている人は誰でも入れる**。アドレスは友達にだけ送り、公開したり、公開ロビーを作ったりしないこと。これは素材の著作権上のリスクも下げる。
- グローバル IPv4 があればルーターでポート転送もできるが、自宅の PC を直接インターネットにさらすことになるので、上の方法を優先すること。

## 操作

| 操作 | 方法 |
|---|---|
| 購入 / 調度センターのレベルアップ / 機変カード選択 | 1 回押して選択、もう 1 回押して確定（`D` でレベルアップ） |
| オペレーターの配置 / 移動 | 整備エリアから盤面のマスへドラッグ → 方向ホイールが出る → 上 / 右 / 下 / 左にスライドして向きを選び、離して確定。中心で離すか「✕ タップでキャンセル」でキャンセル。ドラッグ中はモデルがポインター / 指の下にあり、ポインターのあるマスが配置先になる |
| 向きの変更 | オペレーターを自分のマスにドラッグで戻し、方向を選び直す |
| 売却 / 撤退 / 装備の破棄 | ユニットのいるマスをタップ → 下部ボタンの「売却 +1」「撤退」。盤面のオペレーターを整備エリアにドラッグして撤退させることもできる。整備エリアの装備と術式は「破棄」のみ可能で、配布済みの装備はオペレーターに固定される（オペレーターの売却やエリート合成時に整備エリアへ戻る） |
| 装備 | 装備をオペレーターのいるマスにドラッグする（1 人 2 つまで。満杯だと入れ替えウィンドウが出て、外した 1 つは破棄される）。術式は地面にドラッグして方向を選ぶ |
| 詳細の表示 | ユニット / カードを右クリックまたは長押し（ステータスはリアルタイムの値で、基礎値より高いと緑、低いと赤） |
| ショートカット | `R` 更新 · `F` ロック · `D` レベルアップ · `Q` 選択中のオペレーターを撤退 · `X` 選択中のオペレーターを売却 · `Space` 準備完了 · `Esc` キャンセル / 閉じる |
| 方向ホイールのキーボード操作 | 矢印キーでプレビュー · `Enter` で確定 · `Esc` でキャンセル |
| 一時停止（単独演算） | 戦闘中（最終攻勢 / 隠された核心を含む）に上部バーの「一時停止」を押すか `Space`、再開は「戦闘を再開」（または `Space`）。連合演算の戦闘は一時停止できない |
| スタンプ | 左下の「交流」で、左右にスワイプ（または矢印キー）してテーマを切り替える。クールダウン 1 秒 |
| 観戦 | 自分の戦闘が終わったあと（または準備フェーズ）、左側の仲間のアイコンをタップ →「見に行く」。戦闘に参加しない友達は、ロビーで連合キーを入力して「観戦」を押す（1 つの連合につき観戦者は最大 2 人。0.1.3 で追加） |

ルール・数値・コツの詳細は **[docs/PLAYING.md](docs/PLAYING.md)**（中国語）を参照（ゲーム内の左下にも「遊び方」がある）。

## 開発とテスト

```bash
npm run dev                 # node --watch：サーバーのコードを変えると自動で再起動
node --test                 # 単体＋結合テスト（約 3600 件。素材 / ブラウザがないテストは自動でスキップ）
SP_E2E=1 node --test test/ui/mock.e2e.test.js        # ブラウザの E2E テスト。手元の Chrome が必要（CHROME_PATH でパス指定可）
SP_REAL_E2E=1 node --test test/ui/real.e2e.test.js   # Chrome ＋ダウンロード済みの素材が必要
RENDER_E2E=1 node --test 'test/render/*.browser.test.js'   # 描画テスト。一部はローカル抽出した盤面テクスチャが必要
```

- ゲームデータは `npm run build-data`（`tools/build-data.mjs`）で公式データ表から生成する。`data/*.json` は手で編集しないこと。
- GitHub Actions（[.github/workflows/ci.yml](.github/workflows/ci.yml)）が、Ubuntu と Windows、Node 22 / 24 で `npm ci`、`node --test`、サーバーのスモークテストを実行する。`npm ci` の postinstall が日本語の辞書（手訳の部分）をビルドするので、日本語化のテストも通る。

## 日本語化の中身

上流に日本語表示を足しただけのフォーク。ゲームの仕組みとデータ（`data/*.json`）は上流のままで、変えたのは次の部分。

`?lang=ja` で日本語、`?lang=zh` で中国語。タイトル画面と設定の「中文 / 日本語」でも切り替えられる（ブラウザの言語が日本語なら最初から日本語）。

- 画面の文言は中国語の原文をキーにした `t('…')` で包み、辞書 `i18n/ja/*.json` で日本語に置き換える。辞書にない語は中国語のまま表示される。
- `data/*.json` のオペレーター名・スキル・敵などは読み込み時に置き換える（表示用コピーだけ。戦闘計算とサーバーのデータは中国語のまま）。
- 辞書には**手訳の部分**（画面の文言 `10-ui-*.json`、堅守協定専用のデータ `20-data-*.json`、サーバーの文言 `30-server.json`）と、**日本版の公式データから生成する部分**（`00-official.json`）がある。後者は `tools/i18n-official.mjs` が、日本版クライアントのデータ（[Kengxxiao/ArknightsGameData_Yostar](https://github.com/Kengxxiao/ArknightsGameData_Yostar) の ja_JP）と中国語のデータを ID で突き合わせて作る。**Yostar / Hypergryph の著作物なのでこのリポジトリには入れず（`.gitignore` 済み）、`npm run setup` か `npm run i18n:official` で手元に生成する。** 日本版のデータにまだない新しいオペレーター・敵・モジュールは日本語のテキストがなく、中国語のまま表示される。
- ブラウザが読む `public/i18n/ja.json` は上の辞書をまとめた生成物で、これもコミットしない。`npm install`（postinstall）と `npm run setup` が作る。
- 仕組みと書き方は [`docs/I18N.md`](docs/I18N.md)、用語集は [`i18n/glossary.ja.md`](i18n/glossary.ja.md)。公式の表記を確認できなかった語は用語集に「案」と書いてある。訳の間違いや不自然な表現は Issue か Pull Request で歓迎する。

```bash
node tools/i18n.mjs build      # i18n/ja/*.json → public/i18n/ja.json（検証つき）
node tools/i18n.mjs coverage   # 未翻訳の一覧（code = t() のキー、data = ゲームデータ）
node tools/i18n.mjs lint       # t() の外に残った中国語
node tools/i18n.mjs todo --data effects   # ある data ファイルの未翻訳
npm run i18n:official          # 日本版の公式データから 00-official.json を生成して build
```

翻訳を直すときは `i18n/ja/` の該当ファイルを編集して `build` を実行する（ファイル名順に読み込み、後のファイルが前を上書き。衝突は `build --conflicts` で見られる）。

## 上流の更新を取り込む

```bash
git remote add upstream https://github.com/sganggs/Stronghold-Protocol.git   # 未設定なら
git fetch upstream
git merge upstream/master          # 画面の文言を包んだ t() と上流の UI の変更が衝突しやすい
node tools/i18n.mjs lint           # 上流が足した、t() で包まれていない中国語を探す
node tools/i18n.mjs coverage       # 新しい文言・データの未翻訳を確認
node --test                        # 上流のテストが、t() 化したソースの書き方に合わなくなることがある
```

データが更新された場合は `node tools/i18n.mjs todo --data <名前>` で、新しい未翻訳だけを出せる。公式テキストを作り直すには `npm run i18n:official`。
